# Sagax Amadeus（投研报告审计插件）

报告发出去之前过一遍审计。这个 Skill 讲**怎么调**、**怎么读结果**、以及
**拿到结果之后你可以做什么、绝不能做什么**。

最后一部分最重要。调用只有一行，难的是拿到 D 级之后的行为。

**它不改你的文档。** 只告诉你哪里有问题、为什么、该怎么改。

**判定是确定性的**：比数值、比口径、比来源，不靠模型。所以结论可复现，同样的
文档得到同样的标注，连 id 都一样。**不要试图说服它** —— 它不是一个能被说服的
东西，反复重审也不会得到不同结果。

## 一、什么时候用

- 写完一份要对外的投研报告、点评、路演材料
- 报告里出现任何财务数字或估值指标
- 把多个数据源的数字拼进了同一份材料

**不用的场合**：纯定性讨论、不含数字的流程说明 —— 抽不出可核验的断言，审了
只会告诉你「0 条断言」。

## 二、怎么调

### 优先：MCP 工具

只有一个 `sagax.review`，**最简形态只要一个参数**：

```jsonc
{ "document_path": "/path/to/report.pdf" }
```

服务端会为报告里点了名的财务指标自己去数据源取真值 —— **你不需要准备证据**。

两个可选参数，都不是必须：

```jsonc
{
  "document_path": "/path/to/report.pdf",
  "code": "600519.SH",            // 正文里没写带交易所后缀的代码时，给了更稳
  "annotated_path": "/path/to/annotated.pdf"   // 标注版存哪（仅 PDF 源文档）
}
```

如果你**自己记录了取数结果**，给出来更强 —— 那是你声明「这个数来自这里」，
比服务端事后独立查更贴近你实际用的口径。两者会合并：

```jsonc
{ "document_path": "…", "evidence": [
    {"field": "revenue", "value": 1688.4, "unit": "亿元", "period": "2025A",
     "source": "2025年年度报告", "source_ref": "ann:2025A#p12"}] }
```

其他工具：`sagax.boundaries`（先看会被哪些规则约束）、
`sagax.memory_search` / `sagax.wiki_search`（查本机构的内部口径规定）、
`sagax.runs`（历史审计）、`sagax.usage`（配额还剩多少）。

### 或者：Python SDK

```python
from sagax_amadeus import SagaxAuditClient

client = SagaxAuditClient()          # 读 SAGAX_AUDIT_API_BASE_URL / _API_KEY
result = client.review("report.pdf")
client.download_annotated(result.review_id, "annotated.pdf")
```

## 三、怎么读结果

**先读这两个，其余都是细节：**

```python
result.blocking            # 能不能发。程序判断读这一个
result.coverage_note       # 查了多少、没查多少
```

`coverage_note` 是这个产品最重要的一句话。**「没发现问题」不等于「没有问题」**。
一份只抽到 2 条断言的报告，2 条全对也不代表整篇没问题 —— 它代表几乎什么都没查。

| 评级 | 意思 |
|---|---|
| `A` | 查遍了且都对 |
| `B` | 无严重问题，但有需要补依据或说清口径的地方 |
| `C` | 有站不住的内容，改完再走一遍 |
| `D` | 触发平台红线（有数字完全找不到依据） |

## 四、拿到结果之后 —— 边界在哪

这一节是这个 Skill 的核心。**审计给意见，行动是你的**，但行动有边界。

### ✅ 可以自己改：数据源给出了真值

标注里出现「数据源显示…是 X」时，那是引擎独立查到的值：

```
🔴 3500.0 亿元  [数字算错]
   数据源显示总资产是 3,038.35亿元（2025年，来自 sagax-data）。
```

按它改。**改完重新审一遍**，不要假定改对了。

### ✅ 可以自己改：补上你确实有的来源

标注说「没有依据」，而你的执行轨迹里确实有那次取数 —— 把来源写进正文，或者用
`evidence` 把它交上去重审。

### ⛔ 绝不能做：把查不到依据的数字留在报告里

红线 `p0.evidence_required` **不可关闭**。查不到依据的数字只有两条路：
**补上来源**，或者**删掉它**。

第三条路（加个「约」字、改成区间、换个说法）是**粉饰不是修复** —— 数字还在，
依据还是没有，只是现在更难被发现。

### ⛔ 绝不能做：因为被标了就随手改一个数

引擎只说「没有依据」、没给真值时，你**不知道**正确值是多少。这时改成另一个数，
只是把一个无据的数字换成另一个无据的数字，而且更危险 —— 它现在看起来像核对过。

**停下来去查，或者如实标注「待确认」。**

### ⛔ 绝不能做：把「未核验」说成「已通过」

`coverage_note` 里说没核的部分，在交付时要如实呈现。不要因为审计没报错就宣称
"已通过审计"。

### 🤔 必须问人：口径分歧

引擎说「数据源显示是 X」但你用的是另一个口径（你算扣非、它给归母）—— 这不是
错误，是分歧。**在正文里说明你用的口径**，不要默默改成它的数。

### 🤔 必须问人：工作流审计报出矛盾

结果里 `workflow.problems` 非空时，那是**你的执行过程**有问题，不是措辞问题：

| 类型 | 意思 | 该做的 |
|---|---|---|
| `unverified` | 某一步没有验证器，产出没被检查过 | 补验证器；在那之前该步产出只能标为"未验证" |
| `contradiction` | 标着"已验证"却有数据回放失败 | **别改文档** —— 验证器本身有问题，报给人 |
| `orphan` | 产出了数据但说不清来源 | 补上取数调用或上游依赖 |
| `broken` | 某一步失败了 | 它下游的结论全部作废，重跑 |

这四类**都不能靠改文字解决**。

## 五、几个会让你困惑的地方

**「报错说没有可提取的文字」** —— 你交的 PDF 是图片型的（扫描件或整页转图）。
审计需要文字层才能定位到具体的字。用程序导出的 PDF，或先 OCR。

这一条**会明确报错而不是给你"通过"**：一个字都没读到却回 A 级，比不能用更糟。

**「为什么某些数字没被查」** —— 服务端有三条不猜的规矩，因为猜错会把一个正确
的数字标成错的：

- 认不出证券代码不查（写明 `600519.SH` 这类带后缀的代码，或传 `code`）
- 口径不唯一的词不查（裸写「净利润」不查，「归母净利润」才查）
- 推不出报告期不查（写明「2025年年报」「2025Q3」）

没查的都在 `coverage_note` 里，**不算通过**。

**「同一份报告两次结果不一样」** —— 不应该发生。取数在判定之前完成并落成快照，
判定只看快照。真遇到就是 bug，报给我们。

**「我不认同这个评级」** —— 评级只聚合不新增判断：触发 P0 就是 D，有 HIGH 就是
C。没有可调阈值，也没有申诉通道。要改评级只能改内容。

## 六、一句话总结

**审计告诉你哪里站不住；补依据或者删掉，没有第三条路。**

它查不到的部分要如实说"没查过"，不要说"没问题"。
